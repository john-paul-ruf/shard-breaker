# M13 — Browser Acceptance Tests

## Boundary

- **Path:** `./tests/e2e/`
- **Session-owned pathspec:** `./tests/e2e/**/*`
- **Purpose:** Verify complete player-visible contracts across real browser
  navigation, pointer input, refresh recovery, persistence, responsive layouts,
  reduced motion, and static-site base paths.

## Public Test Surface

- Feature-scoped `*.spec.ts` files
- Small typed fixtures/helpers under `./tests/e2e/`
- Deterministic test hooks limited to seed/profile setup and diagnostics; no hook
  may bypass the same domain transition rules used by production UI

## Dependency and Implementation Rules

- Tests consume the public app surface from M01–M10 and do not modify source
  modules at runtime.
- Prefer accessible role/name locators and observable committed state. Avoid CSS
  selectors tied only to presentation internals.
- Use deterministic seeds and isolated browser contexts. Clear or seed IndexedDB
  explicitly per test; never depend on test execution order.
- Cover Chromium for the normal gate and the configured Firefox/WebKit/mobile
  projects at release milestones.
- Use the orchestration-assigned port. Trace/screenshot/video output belongs in
  ignored test output paths, never in the session lease unless a deliberate
  checked-in fixture is required.
- Do not create a verification-only implementation session. Add acceptance tests
  to the feature session whose disjoint test file set it owns, or pair them with
  that feature's final integration session.

## Required Flow Families

- Start/resume/abandon guard and safe refresh
- Route choice, mandatory boss floor, shop, and recovery idempotency
- Exactly-three reward choice and refresh-safe one-time commit
- Pointer aim/explicit launch/paddle/loss/clear combat behavior
- Boss telegraph/counterplay/reward transition
- Terminal finalization, record/Shards/relic, export/import/reset
- Desktop, tablet, and portrait-phone ordering plus reduced motion
- GitHub Pages base-path asset and reload behavior
